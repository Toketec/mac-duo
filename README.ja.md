# Mac Duo

**MacBook を閉じれば、画面も一緒に折れていく。**

本物のヒンジ角度 → 本物のパースペクティブ → 本物の段階的ブラー。
ネイティブ実装、GPU 処理、最大 120 Hz、サードパーティ依存ゼロ。

折りたたみスマホの開閉アニメーションを触ったことがあって、自分のノート PC でもやってほしいと思ったなら——それがこれです。しかも真面目に作った版です。MacBook の**実際のヒンジ角度**を読み取り、「自分は動いていない」という固定視点でデスクトップを回転するパネルへ再投影し、パネルが視線から離れていく方向へ**物理的な裏付けのある段階的ブラー**を重ねます。そして画面が開ききった瞬間に静かに道を譲ります。

タイマーで角度を装うことも、スライダーで開閉を装うこともしていません。フタが 1 度動けば、映像も 1 度動きます。

> **正直に範囲を明示します：** これは折りたたみスマホの開閉エフェクトに着想を得て、MacBook の底面ヒンジ向けに実装した**独立した成果物**であり、iOS アニメーションのピクセル単位の移植では**ありません**。Apple のアートワーク、ファームウェア、プライベートフレームワークは含まず、**非公開**の Apple HID センサーを使用しています（[制約と正直な注意](#制約と正直な注意) を参照）。

## ハイライト

| | |
|---|---|
| 🔗 **実角度の追従** | 動作中は **8 ms**、静止時は **33 ms** でヒンジ角度を取得。時間ベースの平滑化でオーバーシュートなし。 |
| 📐 **固定視点の投影** | 視点はキーボード空間に固定。パネルが回転しても内容上部の物理的な高さが保たれるため、「折れ」に見えて「潰れ」に見えません。 |
| 🌫️ **本物のガウスブラー** | 1 → 1/2 → 1/4 → 1/8 の Metal Performance Shaders ガウスピラミッドを半径で連続合成。不透明度のフェードではなく被写界深度です。 |
| ⚡ **120 Hz・GPU 常駐** | CADisplayLink が内蔵ディスプレイに追従。パースペクティブとブラーは GPU 上で再利用可能な共有バッファへ。毎フレームの `malloc` も CPU 全画面コピーもありません。 |
| 🪟 **メニューバー常駐** | accessory アプリとして動作。オーバーレイはクリック透過で、キーボードフォーカスを奪いません。 |
| 🔒 **依存ゼロ** | Apple Command Line Tools とシステムフレームワークのみ。パッケージ取得もダウンロードも通信もありません。 |
| 🙈 **データは外に出ない** | フレームを取得するのはフタが動いている間だけ。処理はメモリ内、保存も送信もしません。 |

## 仕組み

```
┌──────────────┐   HID フィーチャレポート ┌──────────────────┐   Metal + MPS    ┌──────────────┐
│ ヒンジセンサー │ ────────────────────► │ FoldState        │ ───────────────► │ オーバーレイ  │
│ （読み取り専用）│  8 ms / 33 ms 適応的  │ 写像・平滑化・予備 │  透視 + ガウス + 暗化│ 内蔵画面のみ  │
└──────────────┘                        └──────────────────┘                  └──────────────┘
```

1. **取得。** 読み取り専用の IOKit HID フィーチャレポートから現在のヒンジ角度を得ます。レポートの書き込みも、センサー校正への介入も一切ありません。ポーリング周期は動きに応じて適応し（動作時 8 ms、静止時 33 ms）、レポートが途切れると自動で切断・再接続します。
2. **写像。** `FoldMath.openness` が角度を進捗へ写像し、範囲は校正できます。`FoldMath.referenceUV` は**固定視点**からのレイ／平面交差で全ピクセルを再投影します。視点はパネル長の `2.4 ×` 前方、高さは全開時のパネル上端のワールド高さに一致します。パネルが回転してもこの高さは動かない——これが「折れ」に見える理由です。ヒンジ辺が固定軸で、上に余った領域は黒、物理画面の外へ出た投影は引き伸ばさずクリップします。
3. **描画。** 投影結果は多段ガウスピラミッドを通り、半径で連続合成され、ヒンジ側へ向けて暗化されます。完成フレームは GPU が再利用可能な共有バッファへ書き込み、ネイティブ AppKit ビューが描画します——透明なメニューバーアプリでの `CAMetalLayer` 表示不具合を意図的に避ける構成です。

各層のタイミングは独立しています：ジオメトリは display link（最大 120 Hz）、デスクトップ取得は最大 60 Hz、センサーは最大 125 Hz。`FoldState` は指数関数的アプローチで平滑化し（時定数 45 ms、オーバーシュートなし）、45° 以下は折りたたみ終端状態を保持するため、見えない角度域で遷移進捗を消費しません。

| ヒンジ角度 | 表示 |

| **≥ 上限**（既定 **135°**） | エフェクト停止——そのままのデスクトップ、オーバーヘッドゼロ。 |
| **上限 → 45°** | 連続的な折りたたみ。パースペクティブ、段階的ブラー、ヒンジの暗化がリアルタイムで追従。 |
| **≤ 45°** | 折りたたみ終端状態で保持——本当に見えない範囲はアニメーションしません。 |
| **校正** | 「完全に鮮明」にしたい角度でフタを止め、**現在の角度で校正**を押すだけ（65°–135° に制限）。ハードウェアは変更せず、写像だけを調整します。 |
| **センサー喪失／完全閉蓋** | 自動的に鮮明なデスクトップへ復帰。リーダーは自ら再接続します。 |

## 動作環境

- Apple Silicon の Mac（本リポジトリは M2 Max でビルド・計測）
- macOS 14 以降
- Apple Command Line Tools（`xcode-select --install`）——Xcode プロジェクトもパッケージマネージャも不要
- *任意：* 画面収録の権限（完全なデスクトップエフェクトに必要）。未許可でも基本モード（角度に応じたブラーと暗化）で動作します。

## ビルドと実行

### ビルド済みバイナリ（最短）

`dist/` にすぐ実行できる **`Mac Duo.app`** と `MacDuo-1.2.0-arm64.zip` を同梱しています —— Apple Silicon、macOS 14 以降、ad-hoc 署名。

```sh
git clone https://github.com/Toketec/mac-duo.git
cd mac-duo
xattr -dr com.apple.quarantine 'dist/Mac Duo.app'   # ダウンロード隔離フラグを解除
open 'dist/Mac Duo.app'
```

ad-hoc 署名のため、初回起動時に Gatekeeper が確認します（右クリック →「開く」でも可）。最新のコードを動かしたい場合は、下記のソースからのビルドが確実です。

### ソースからビルド

```sh
git clone https://github.com/Toketec/mac-duo.git
cd mac-duo

./scripts/build.sh      # 生成物：build/Mac Duo.app
./scripts/run.sh        # 必要ならビルドしてから起動
```

ビルドはローカルの ad-hoc 署名で、有償の開発者証明書は不要です。再ビルドごとに再署名されるため、macOS が画面収録の権限の再確認を求めることがあります。その後：

1. メニューバーのノート PC アイコンをクリック → 「実際のデスクトップエフェクトを有効化」。
2. *システム設定 → プライバシーとセキュリティ → 画面とシステムオーディオの収録* で **Mac Duo** を許可（終了して再度開くよう求められる場合があります）。
3. ゆっくりフタを閉じて開くと、アニメーションが連続して追従します。「展開アニメーションをプレビュー」で画面を動かさずに確認もできます。

ショートカットとライフサイクル：**⌃⌥⌘D** でグローバルに一時停止／再開。スリープとロックでオーバーレイは自動的に隠れ、起床／ロック解除後に復帰します。アプリを終了すればすべて停止——ログイン項目も常駐デーモンもありません。

## 検証とベンチマーク

```sh
./scripts/test.sh              # ロジックと境界テスト、diagnose、プレビュー描画、署名検証
./scripts/test-native.sh       # 約 2 秒の実ウィンドウ：CVPixelBuffer → Metal → AppKit 描画
./scripts/test-performance.sh  # 約 6 秒の全画面合成負荷、build/performance/result.json に出力
```

状態テストは、センサーレポートのデコード、45°/90°/135° の境界、最大角度での投影恒等、ヒンジの固定、観察レイが物理パネルとともにずれないこと、センサー喪失からの復帰、一時停止、プレビュー終了、起床、オーバーシュートのない平滑化を網羅します。

GPU チェックは合成フレームと 3 種類のパネル状態を描画し、個人のデスクトップには一切触れません。追加のエントリポイント：

```sh
'build/Mac Duo.app/Contents/MacOS/MacDuo' --diagnose
'build/Mac Duo.app/Contents/MacOS/MacDuo' --render-previews build/previews            # 5 段階の開度
'build/Mac Duo.app/Contents/MacOS/MacDuo' --render-previews build/sweep --sweep 41    # 高密度スイープ（GIF 用）
```

`--sweep N` は等間隔の開度を `N` 枚描画します（`fold-000.png` … `fold-100.png`）。このページ冒頭のアニメーションはまさにこの方法で生成しています。

既定の 5 段階描画の挙動は変わらないため、`scripts/test.sh` の出力も従来どおりです。

## 性能データ

`./scripts/test-performance.sh` を M2 Max、1512×982 のデスクトップソース、60 Hz のソース更新、120 Hz のジオメトリ要求で計測：

| レンダラ | 描画回数／秒 | フレーム間隔 P95 | 描画時間 P95 |
|---|---|---|---|
| **現行**（display link + 共有バッファ） | ~120 | 8.56 ms | 7.07 ms |
| 旧版（60 Hz `Timer`） | ~103 | 16.85 ms | 9.99 ms |

生の JSON は `build/performance/result.json` に保存されます。これは合成負荷の結果であり、あらゆるデスクトップ負荷や物理的な開閉で 120 fps を保証するものではありません。

ライブ診断は `~/Library/Application Support/MacDuo/status.json` に書き出されます（プロセス ID、角度、権限、GPU の送信／完了／表示フレーム数、描画と GPU のミリ秒、フレームクロック）。**デスクトップ画像は含みません**。ターミナルから `--diagnose` を実行した場合、権限の読み取り値はその診断プロセスのものなので、状態ファイルの PID と更新時刻を必ず照合してください。

## プライバシー

- 画面フレームを取得するのはフタが**動いている間だけ**（`ScreenCaptureKit`、フィードバックを避けるため本アプリは除外）。処理はすべて GPU によるメモリ内処理です。
- 保存も送信もせず、アプリはネットワーク接続を開きません。開発時の参考調査はローカルプロキシ経由で、製品版アプリの外部通信はゼロです。
- 上記の状態ファイルには数値しか含まれません。

## FAQ

**スリープ設定は変更されますか？** いいえ。閉蓋時のスリープは従来どおりで、画面が消えている間は単にアニメーションが見えないだけです。

**最初の一瞬だけ基本モードなのはなぜ？** 画面キャプチャの初回フレームに少し時間がかかるためです。それまでは角度に応じたブラー／暗化の基本モードになり、その後自動で完全なエフェクトへ切り替わります。

**座った位置とパースペクティブが少し違うのは？** 視点はキーボード空間の固定点で、カメラによる視線追跡は行いません。実際の姿勢が錯覚の説得力を左右します。

**Intel Mac や外部ディスプレイでも動きますか？** エフェクトは内蔵画面のみ、センサーインターフェースは Apple Silicon 世代のものです。計測したマシン以外での動作は保証しません。

**プライベート API を使っていますか？** **非公開だが読み取り専用**の HID センサーインターフェース（Apple ベンダー、usage page `0x20`、usage `0x8A`、フィーチャレポート 1）を使用しています。プライベートフレームワークの呼び出し、ファームウェアの変更、書き込みは一切ありません。

## 制約と正直な注意

- 折りたたみスマホの開閉に着想を得て MacBook の底面ヒンジに適合させた独立した近似実装であり、iOS アニメーションのピクセル単位の再現ではありません。
- HID 角度インターフェースは非公開です。本リポジトリのマシンで検証済みで、**すべての Mac での動作を主張しません**。
- ロック画面と完全閉蓋状態は macOS の管理下にあります。ロック解除後にエフェクトが復帰します。
- センサーが切断されると自動的に鮮明なデスクトップへ戻ります。クラッシュも、偽の「折り目」の残像もありません。
